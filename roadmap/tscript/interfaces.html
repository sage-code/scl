    Interfaces and Contracts

    Interfaces turn implicit assumptions into explicit agreements. This is essential for teamwork and long-lived front-end applications.

    1. Interface basics

    interface User {
  id: string;
  email: string;
  active: boolean;
}

    2. Optional and readonly fields

    interface Profile {
  readonly id: string;
  displayName?: string;
}

    3. Function interfaces

    interface Formatter {
  (value: number): string;
}

const currency: Formatter = (v) => `$${v.toFixed(2)}`;

    4. Extends and composition

    interface Timestamped { createdAt: string; updatedAt: string; }
interface Product extends Timestamped { id: string; name: string; price: number; }

    5. API contract modeling

    Define external DTO interfaces and map them to internal domain interfaces. Do not leak unstable backend formats into UI components.

    6. Interface vs type alias

    Use interfaces for object contracts and public API surfaces. Use type aliases for unions, primitives, and advanced type composition.

    7. Contract evolution and versioning

    When backend contracts change, keep versioned interfaces and explicit adapters during migration.

    8. Review checklist

    1. Is every API response typed?
    2. Are optional fields intentionally optional?
    3. Are old/new schema versions handled safely?

    9. Practice

    Define interfaces for auth session, user profile, and role-based navigation configuration.
