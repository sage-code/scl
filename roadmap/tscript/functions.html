    Typed Functions and APIs

    Functions are architectural boundaries. If function contracts are weak, the whole application becomes fragile.

    Designing signatures

    type PriceRequest = { amount: number; currency: "USD" | "EUR" };

type PriceResponse = { ok: true; formatted: string } | { ok: false; reason: string };

function formatPrice(input: PriceRequest): PriceResponse {
  if (input.amount < 0) return { ok: false, reason: "Negative amount" };
  return { ok: true, formatted: `${input.currency} ${input.amount.toFixed(2)}` };
}

    Overloads and trade-offs

    Use overloads when callers need different signatures. Keep overload count low and implementation explicit.

    Async contracts

    Return typed result objects or typed exceptions. Avoid returning ambiguous shapes.

    Callback typing

    Always type callback arguments and return values. Unclear callbacks create hidden runtime bugs.

    Error handling strategy

    Choose one pattern per layer: either throw typed errors or return typed result unions. Mixing both causes confusion.

    Practice

    Build a typed fetchUserProfile function with explicit success and failure contracts and use it in UI rendering code.
