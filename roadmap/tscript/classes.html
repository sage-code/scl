    Classes for UI Domain Models

    Classes are useful when data and behavior must stay together with strict invariants.

    1. Class structure

    class Counter {
  private value = 0;

  increment(): void {
    this.value += 1;
  }

  get current(): number {
    return this.value;
  }
}

    2. Constructor and parameter properties

    class Money {
  constructor(
    private readonly cents: number,
    private readonly currency: "USD" | "EUR"
  ) {}

  format(): string {
    return `${this.currency} ${(this.cents / 100).toFixed(2)}`;
  }
}

    3. Access modifiers

    • public: visible everywhere.
    • private: visible only in class.
    • protected: visible in class and subclasses.
    • readonly: can only be assigned in constructor/field init.

    4. Getters and setters

    Use getters/setters to validate state transitions instead of exposing raw field mutation.

    5. Abstract classes

    abstract class Repository {
  abstract getById(id: string): Promise;
}

    6. Composition over inheritance

    Prefer small collaborating classes over deep hierarchies. Composition is easier to test and refactor.

    7. Testing classes

    Test public behavior and invariants. Avoid tests that lock internal implementation details.

    8. Class anti-patterns

    1. God classes that manage unrelated concerns.
    2. Public mutable fields everywhere.
    3. Hidden side effects in getters.

    9. Practice

    Implement a SessionState class with timeout rules and a separate SessionFormatter helper using composition.
