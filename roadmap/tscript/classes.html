    Classes for UI Domain Models

    Most UI state can be modeled with objects and functions. Use classes when behavior, invariants, and lifecycle logic need strong encapsulation.

    Class fundamentals

    class Money {
  constructor(private readonly cents: number, private readonly currency: "USD" | "EUR") {}

  format(): string {
    return `${this.currency} ${(this.cents / 100).toFixed(2)}`;
  }
}

    Access modifiers and intent

    private protects internal details. public exposes stable APIs. protected should be used carefully and only when inheritance is deliberate.

    Readonly invariants

    Readonly fields protect domain rules and prevent accidental state mutation from external code.

    Inheritance vs composition

    Prefer composition for UI architecture. Deep inheritance often makes debugging and testing harder.

    Testing class behavior

    Test class methods against domain rules, not internal implementation details.
