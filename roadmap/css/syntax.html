    Syntax and Selectors

    CSS tells the browser how elements should look. A CSS file is a sequence of rules: selector + declarations.

    Rule anatomy

    Every rule has two parts:

    • Selector: chooses the element(s).
    • Declaration block: one or more property: value; pairs.
    p {
  color: #e2e8f0;
  line-height: 1.6;
}

    Where to write CSS

    Use external CSS files for maintainability. Inline and internal styles are useful only for quick tests.

    Style location Use case Recommendation
    Inline (style="...") One-off quick debugging Avoid for production pages
    Internal (<style>) Small isolated demos Acceptable for prototypes
    External (.css file) Real websites and reusable styles Best practice

    Selector basics

    /* Element selector */
h1 { color: #22c55e; }

/* Class selector */
.card-title { font-weight: 700; }

/* ID selector */
#hero { padding: 2rem; }

/* Group selector */
h2, h3 { margin-top: 1.25rem; }

    Cascade and specificity

    The browser resolves style conflicts in this order:

    1. Importance (!important beats normal declarations).
    2. Specificity (ID selector beats class selector, class beats element).
    3. Source order (later rule wins when specificity is equal).
    .notice { color: #f59e0b; }
#banner .notice { color: #38bdf8; } /* more specific, so it wins */

    Color notation

    Use whatever notation improves readability for your team:

    • #0ea5e9 (hex)
    • rgb(14 165 233) (RGB)
    • hsl(199 89% 48%) (HSL)
    • white, black (named colors)

    Quick practice

    Create one styles.css file and style this HTML with selectors:

    <article id="intro" class="card">
  <h2 class="card-title">CSS Practice</h2>
  <p>Write a clean first stylesheet.</p>
</article>

    Target #intro, .card-title, and p. Add spacing, colors, and readable line-height.
