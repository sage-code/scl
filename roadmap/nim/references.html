    Nim References & Learning

    This final page gathers what you need for a life of Nim after this track: where to run code instantly, where the truth lives, which channels answer real questions, which exercise sets build fluency, and which repositories are worth reading. Everything listed here is free.

    The shortest path remains your own machine: install the toolchain from the official install page and every demo and project in this track runs with one command. The resources below support that path at every level.

    nim --version                 # confirm the toolchain you installed
nim c -r 01_hello.nim         # compile, link, run — the whole loop
nimble --version              # the package manager ships with Nim

    Playgrounds & Online Compilers

    When you cannot install anything — a locked-down machine, a borrowed laptop — a browser playground still lets you experiment. These run the same compiler you would install locally, so what you learn there transfers unchanged.

    Official Documentation

    Nim's documentation is generated from the source and kept current. When this track and the documentation disagree, the documentation wins — and the manual is the normative one.

    The Documents That Matter

    SourceWhat it is
    Nim ManualThe specification: type system, generics, effects, pragmas, memory model. Dense but authoritative
    Standard Library IndexEvery module, proc and type with signatures and examples — your most-visited page
    Tutorial, Part 1The language for readers already fluent in another one; parts 2 and 3 continue into macros and metaprogramming

    Backend TargetsC, C++, Objective-C and JavaScript backends, and what each one can do

    Community

    Nim is a small, responsive community. Ask a precise question — the smallest program that shows the problem, plus the compiler version — and you will usually get an answer from someone who knows the compiler internals.

    Where to Ask and Follow

    ChannelWhat it is
    Nim ForumThe official discussion forum: questions, RFC-style proposals, release announcements
    DiscordReal-time help; the #help channel is the fastest route to an answer
    Matrix / Gitter bridgeThe same rooms for people who prefer open protocols
    Issue TrackerReport compiler bugs and read the ones others found — a free education in edge cases
    Official BlogRelease notes and design essays from the core team
    Community DirectoryThe canonical, always-current list of channels, meetups and package sources

    Practice and Exercises

    Reading teaches recognition; typing teaches production. These two systems give you graded problems with automated feedback, which is the fastest way to move from "I understand" to "I can write it".

    Open-Source Samples

    Reading code written by maintainers consolidates style faster than any guide. Start small, then follow the imports downwards.

    How to Choose & Next Steps

    Follow this ladder and you will never be stuck for what to do next.

    A Practical Ladder

    • Finish this track, running every lab example and building each study project.
    • Work the Exercism Nim track for feedback on style and idiom.
    • Read the manual sections on the features you have already used — they will mean more now.
    • Take the metaprogramming tutorial slowly, and write one macro you actually need.
    • Publish a small library to nimble.directory — packaging it will teach you more about the build system than any reading.
    • Read one module of lib/pure/ per week and try to simplify it; you will learn what good Nim looks like.

    Welcome to the Nim community — a language small enough to understand completely, and fast enough to keep.
