HTML Forms

Forms collect data from users. Login pages, search bars, contact forms, and checkout pages all use the same core HTML concepts.

Form basics

Every form starts with <form>. Inside it, you place labels, inputs, and buttons. 

<form action="/submit" method="post">
    <label for="name">Name</label>
    <input id="name" name="name" type="text">
    <button type="submit">Send</button>
  </form>

Action and method

  • action: where form data goes.
  • method="get": appends data to URL (good for search/filter).
  • method="post": sends data in request body (better for sensitive input).

Common inputs

These input types cover most beginner projects:

  • text, email, password
  • number, date, url
  • checkbox, radio
  • submit, reset

Labels and accessibility

Always pair inputs with labels. This improves usability and accessibility. 

<label for="email">Email address</label>
  <input id="email" name="email" type="email" required>
The for value on <label> must match the input id.

Validation basics

HTML provides built-in validation before any JavaScript is added. 

<input type="email" required>
  <input type="password" minlength="8" required>
  <input type="number" min="1" max="10">

Grouping related fields

Use <fieldset> and <legend> to group related controls. 

<fieldset>
    <legend>Contact preferences</legend>
    <label><input type="checkbox" name="email_updates"> Email updates</label>
    <label><input type="checkbox" name="sms_updates"> SMS updates</label>
  </fieldset>

Example contact form

<form action="/contact" method="post">
    <label for="full_name">Full name</label>
    <input id="full_name" name="full_name" type="text" required>

    <label for="user_email">Email</label>
    <input id="user_email" name="user_email" type="email" required>

    <label for="message">Message</label>
    <textarea id="message" name="message" rows="5" required></textarea>

    <button type="submit">Send message</button>
  </form>

Common beginner mistakes

  1. Missing name attribute (data will not be sent).
  2. Using placeholder as label (bad for accessibility).
  3. Nesting a form inside another form (invalid HTML).
  4. Using only client-side validation for critical checks.
