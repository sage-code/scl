Lab Topics

    What is accessibility?

    Accessibility means your page can be used by everyone, including people using screen readers, keyboard navigation, zoom, or high-contrast settings.

    Accessible HTML is not an advanced extra step. It is part of correct HTML. If your structure is clean, accessibility becomes much easier.

    Use semantic landmarks first

    Landmarks help users and assistive tools jump quickly through the page. 

    <header>...</header>
<nav>...</nav>
<main>...</main>
<footer>...</footer>

    Labels and forms

    Every input should have a visible label. The label text explains what the field expects. 

    <label for="email">Email address</label>
<input id="email" type="email" name="email" required>

    Images and alt text

    • Informative images need useful alt text.
    • Decorative images can use alt="".
    • Avoid text inside images when possible.

    Keyboard and focus

    Many users navigate only with keyboard. Your page should work with Tab, Enter, and Space keys.

    • Use real buttons for actions.
    • Use links for navigation.
    • Do not remove visible focus outlines.

    ARIA: use only when needed

    ARIA can help, but native HTML is usually better. Start with semantic tags first. Add ARIA only when native elements cannot express behavior clearly.

    Rule of thumb: "No ARIA is better than bad ARIA." Choose native elements whenever possible.

    Quick beginner audit

    1. Can I navigate the page with keyboard only?
    2. Do all form fields have labels?
    3. Do all meaningful images have alt text?
    4. Are headings in logical order?
    5. Can I understand the page without color alone?
