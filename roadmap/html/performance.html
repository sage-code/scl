Site Performance for Beginners

Fast pages feel better, rank better, and convert better. The good news: basic HTML performance wins are simple and repeatable.

Why performance matters

When a page loads quickly, users stay focused. Slow pages create friction and cause visitors to leave early. Performance also affects accessibility: people on low-end devices or poor networks benefit the most from fast pages.

Optimize images first

  • Use modern formats when possible (for example WebP).
  • Resize images to the display size; avoid huge source images.
  • Set descriptive alt text and width/height when practical.
  • Use lazy loading for non-critical images.
<img
  src="/assets/images/example.webp"
  alt="Code editor preview"
  width="960"
  height="540"
  loading="lazy"
>

Load CSS and JavaScript wisely

Render-critical CSS should be available early. JavaScript that is not needed immediately should be deferred. 

<link rel="stylesheet" href="/assets/css/sage.css">
<script src="/assets/js/sage.js" defer></script>

Use caching headers

Caching lets the browser reuse files between visits. Static assets can usually have longer cache lifetimes than HTML pages.

Practical rule: long cache for versioned assets (CSS/JS/images), shorter cache for HTML documents that change often.

Measure, then improve

  1. Open browser DevTools and run Lighthouse.
  2. Review Core Web Vitals and largest resource files.
  3. Fix one bottleneck at a time (usually images first).
  4. Re-test after each change.

Quick performance checklist

  • Images are compressed and correctly sized.
  • Non-critical scripts use defer.
  • Only necessary CSS and JS are loaded.
  • Cache strategy is configured for static files.
  • Page is tested on mobile network conditions.
