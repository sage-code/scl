Semantic HTML

Semantic HTML means choosing tags by meaning, not by appearance. This makes your pages easier to read, easier to maintain, and more accessible.

Semantic structure improves readability and accessibility

Why semantics matter

  • Screen readers understand page regions better.
  • Search engines understand content purpose better.
  • Developers can maintain layout faster.

Core semantic tags

Tag Use it for
header Top region of page or section.
nav Primary navigation links.
main Main unique content of the page.
section Thematic grouping of related content.
article Self-contained piece of content.
aside Related side content, not central flow.
footer Closing metadata, legal text, secondary links.

Page layout example

<body>
  <header>
    <h1>My Site</h1>
    <nav>...</nav>
  </header>

  <main>
    <article>
      <h2>Article title</h2>
      <p>Article content...</p>
    </article>
  </main>

  <footer>Copyright 2026</footer>
</body>

Semantic content tags

Some semantic tags are perfect for rich content and documentation.

  • figure + figcaption for images with captions
  • time for dates and time values
  • details + summary for collapsible explanations
  • mark for highlighted text

Semantic tags vs div

Use <div> when no semantic element fits. If the content has a clear purpose (navigation, article, footer), prefer a semantic tag.

Simple rule: if you can name the section meaningfully, there is probably a semantic tag for it.

Common mistakes

  1. Using many <div> tags when semantic tags are available.
  2. Adding multiple <main> elements on one page.
  3. Using headings out of order.
  4. Using semantic tags only for style, not meaning.
