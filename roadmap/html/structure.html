    Why structure matters

    A good HTML page is easy to read, easy to maintain, and easy for tools to understand. Think of HTML structure like a building plan: if the structure is clear, everything else becomes easier.

    Beginners usually focus on "how it looks" too early. Start with "what it means" first. A clean structure helps when you add CSS, JavaScript, SEO metadata, and accessibility support.

    The page skeleton

    Every modern page starts with a small, predictable skeleton. Learn this once, and reuse it for all projects. 

    <!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Page Title</title>
</head>
<body>
  <header>...</header>
  <main>...</main>
  <footer>...</footer>
</body>
</html>

    What belongs in head

    • Metadata: character set, viewport, SEO description.
    • Title: shown in browser tab and search previews.
    • Links: CSS files, favicon, canonical URL.
    • Structured data: optional JSON-LD for rich search results.

    Body layout with landmarks

    Use meaningful landmark tags so humans and assistive tools can quickly understand your layout.

    • <header> for top branding and primary navigation.
    • <main> for the page's unique content.
    • <section> for grouped content blocks with a heading.
    • <footer> for legal info and extra links.

    Nesting and reading order

    Keep your nesting shallow and logical. Do not jump from <h1> to <h4> without reason. Use heading levels in order so screen readers and search engines understand page hierarchy.

    Tip: Before styling, read your HTML like an outline. If it reads clearly as plain text, your structure is probably good.

    Mini checklist

    1. Doctype and language are set.
    2. Head has title, description, and viewport.
    3. Page uses semantic landmarks.
    4. Heading levels are in a natural order.
    5. Content can be understood without CSS.
