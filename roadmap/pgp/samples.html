    Study Projects

    Short examples show syntax; real codebases show how a paradigm shapes architecture, error handling, and module boundaries at scale. This page lists public open-source projects chosen because each one commits clearly to a specific paradigm. Pair this page with Demo Examples and References.

    How to Read a Codebase for Its Paradigm

    When inspecting a repository from a paradigm perspective, ignore build boilerplate at first and ask four targeted questions:

    1. Where does state live? Is it encapsulated inside objects, threaded through pure functions, held in actor mailboxes, or derived from event streams?
    2. How does control flow? Look for loops, recursion, pattern matching, message passing, or constraint search.
    3. How are errors represented? Compare exceptions, algebraic result types, and supervisor restarts.
    4. How are modules composed? Notice whether extension happens through class inheritance, type classes/traits, interfaces, or higher-order functions.

    Practice Lab

    Apply the reading method above to consolidate the roadmap:

    1. Trace one AST pass. Open a small writer module in jgm/pandoc and list the data types it transforms without mutating state.
    2. Compare two concurrency models. Contrast an Erlang gen_server callback module with a goroutine-and-channel worker from Go.
    3. Rewrite a loop declaratively. Take one imperative filter-and-aggregate loop you wrote recently and express it in both functional (map/filter/reduce) and logic (Prolog rules) styles.
