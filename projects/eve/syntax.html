Lab Topics

Eve Syntax

Eve uses short English keywords without abbreviations, explicit block terminators and a semicolon at the end of every statement. Blocks are not delimited by braces. Ada, Ruby, Fortran and Python influenced the design.

Design Strategy

Eve balances an explicit, verbose syntax that is easy to learn with a concise syntax that is easy to use. Keywords say what a statement does: new creates a variable, let executes an assignment or an expression, done closes a block: new a := 1; let a += 1;.

Hello World

The classic first program prints one line to the console:

# demo: hello world
driver hello is

  process main is
    ** main process
    print "Hello World!";
  return;
end hello;

The file is hello.eve: a driver named hello, with one main process that prints "Hello World!". The driver name and the file name are the same.

Syntax Elements

The next program shows most syntax elements. Each one is described later on this page and on the following pages.

# Eve programs start with a driver
driver syntax_elements is

  ** define two global lambda expressions
  set add = (p1, p2: Integer) => (p1 + p2);
  set sub = (p1, p2: Integer) => (p1 - p2);

  process main(a, b: Integer) is
    ** the process uses the arguments a and b
    print "param1: \#{a}, param2: \#{b}";

    ** define local variables
    new v1, v2 :Integer;

    let v1 := add(4, 5);
    new v2 := sub(5, 3);

    ** print the results
    print ("result:", v1); ** result:,9
    print ("result:", v2); ** result:,2
  return;
end syntax_elements;

Punctuation

  • Expressions use infix operators, like Java and most languages.
  • A comma separates the elements of a list and the arguments of a call.
  • A statement usually starts with a keyword and always ends with a semicolon ;.
  • A declaration header ends with the keyword is: driver hello is.
  • A block ends with its terminator keyword: return, end, done, or repeat for a loop tested at the end.
  • Regions and nested blocks are indented.

Source Text

Before the parser sees any statement, the lexer reads characters and turns them into tokens: comments, names, literals, operators and delimiters. This section and the next ones describe these lexical rules.

Encoding and Lines

  • Source files are UTF-8 text with the extension .eve.
  • Lines end with LF or CR+LF; both are valid.
  • A statement ends with ;, not with the end of the line, so it can span several lines.

Comments

Eve comments follow Markdown where possible: # and ## are titles, ** is a note. Block comments use /* ... */, as in most languages.

Comment Forms

FormWhere it startsEndsSpans linesNestsUse
#!line 1, column 0end of linenonoshebang of a free script
#column 0 onlyend of linenonotitle
##column 0 onlyend of linenonosubtitle
**anywhere: column 0, indented, or after codeend of linenonoline and end-of-line notes
(** ... **)inside an expression**)yesnoexpression comment
/* ... */anywherethe first */yesnoblock comment, notes, disabled code

Notes:

  • Block comments do not nest: in /* a /* b */ c */ the comment ends after b. To comment out code that holds comments, use ** lines or expression comments inside it.
  • //, -- and boxed +--- ... ---+ comments are not Eve.
  • ** always starts a comment, so the power operator is ^.
  • After the return; that ends a script, notes can follow in a block comment.

Example

# comments in Eve
/*-----------------------------------------------
  A block comment can describe the whole script.
  It can span many lines.
-----------------------------------------------*/
driver comment_demo is

  process main is
    ** a note on its own line
    new a = 0, b = 1 :Integer;

    ** an expression comment can sit inside an expression
    let a := a + b * (** first factor **) (a - 1); ** end-of-line note
  return;
end comment_demo;

/* Final notes:
   notes after the end of the script use a block comment.
*/

Identifiers

An identifier names a variable, a constant, a type or a subprogram.

  • It starts with a letter (a..z, A..Z), followed by letters, digits and underscores.
  • It has at most 42 characters.
  • Names are case-sensitive: Point and point are two names.
  • It cannot end with an underscore or contain two consecutive underscores.
  • It cannot contain -, which is the minus operator: a-b means a - b.
  • _ alone is the void variable: it accepts any value and discards it.

Prefix and Sigil

A prefix is written in a declaration but is not part of the name: the variable is used without it. A sigil is part of the name and is always written.

SymbolKindMeaning
*prefixvararg parameter: *args
@prefixinput/output parameter or named result: @result
$sigilsystem-wide variable: $error
!suffixa stochastic function: its result can differ for the same arguments, random!(), next!(); a method that changes shared state: o.record!()

Visibility is not a prefix: it is a word in front of a declaration, public, protected or private in a class (see Classes), and the export list in a module (see Modules).

Assign Keywords

Every statement that binds a value starts with a keyword, so the reader sees what it does. set creates a constant and new creates a variable: new a := 0;. let executes an assignment or an expression on names that exist: let a := a + 1;, let a += 2;, let lst -> x;. A statement can change one variable and create another one: new x <- lst; creates x with the first element of lst and removes it from the list (no let needed); let lst -> new x; removes the last element of lst into a new variable x. A class called like a function builds an object: new p := Point(1, 2);.

Keyword Description
let Execute an assignment or an expression on existing names: let x := 1;, let x += 1;, let x << 2;, let lst -> new x;, let f(x);. Works with unary and binary operators, and with method and function calls
set Create global constant or class property
new Create variables or object attributes: new x := 0;, new copy :: original;, new self.x := x;. Inside a statement, new before a name creates that name: let lst -> new x;. A statement that starts with new may change the other names it uses: new x <- lst; changes lst. Redeclaring a name in the same scope is an error
pop Can create a new local variable from element of a collection

Globals and Initialization

Global Variables

A script can define global variables in its scope, outside any process. A global holds a primitive value or a reference to an object. It is declared with set and changed later with an assignment, without keyword. Globals do not use a sigil. All globals share one memory space, so each name is unique.

...
** define global states
  set s = "test" :String;

  ** two integers
  set a :Integer;
  set b :Integer;

  ** one Real variable
  set d = 0.5 :Real;
...

Globals are static, defined in the module scope. set creates a global state; an assignment changes it in a process or subprogram, with an operator such as :=, ::, += or -=. The compiler reports an error when a variable is created twice with set, or when set is used inside a process or subprogram.

Initial Value

The initializer = is the light assignment: it gives the first value of a variable from a data literal. The type is inferred from the literal, or given after :. = is used only for initial values, in a declaration and for the default of a parameter; a variable is changed with := (an expression) or :: (a clone), never with =. = is not an expression: it returns no value and does not chain.

The assignment := infers the type from the right side, evaluates the whole right side, and is a statement, not an expression. When = is followed by an expression instead of a literal, the compiler warns and treats it as :=.

process main is
  new a = 5;                   ** literal, type inferred: Integer
  new b = 5 :Real;             ** literal and explicit type
  new x := a + 2;              ** expression: use :=
  let a := 7;                  ** a change uses :=, never =
return;

Zero Values

A variable declared without a value gets the zero value of its type: 0 for Integer, 0.0 for Real, "" for String. Composite types start empty: (), [] or {}, the empty set ∅.

Several Variables

One declaration can initialize several variables. The type after the last value applies to every name: new a = 1, b = 2 :Integer; is the same as new (a = 1, b = 2) :Integer;. A list of names takes one value for all of them, or one value each:

...
process main is
  new a = 1, b = 2 :Integer;   ** preferred: each name with its value
  new (x, y, z) = 0.5;         ** one value for all, type inferred: Real
  new (m, n) = (1, 2);         ** one value each
  ...
return;

Expressions

An expression is evaluated to a value. It is built from identifiers, literals, operators and function calls, and can be grouped with round parentheses.

  • Expressions combine into larger expressions.
  • The type of an expression is found by type inference.
  • An expression is assigned to a variable with := or used as an argument.
  • Parentheses make the order of operations explicit.

Printing Expressions

print and write are methods. Their arguments are a list of expressions, mapped to parameters by position or by name. A method has one parameter list only. Optional parameters that follow the vararg parameter must be named in the call: print is declared method print(*args, separator = ",") and called print (1, 2, 3, separator: " ");. print separates values with its separator parameter (default ",") and ends with a new line; write adds no separator and no new line.

## simple expressions
process main is
  print 10;
  write "this is a test";
  print;                         ** ends the line started by write

  ** grouping with ()
  print (10 + 10 + 15);          ** numeric expression
  print (10 > 5) or (2 < 3);     ** logical expression

  ** a list of expressions
  print (1, 2, 3);                            ** 1,2,3
  print (1, 2, 3, separator: " ");            ** 1 2 3

  ** write does not add a new line
  write (1, 2);
  write (3, 4);
  print;                         ** 1234
return;

Assign Expression

The assignment := transfers a native (primitive) value by copying it. For an object, it shares the reference: both variables point to the same object, and a change through one is visible through the other.

** assignment forms
  ...
  new identifier1 := literal;         ** constant literal
  new identifier2 := expression;      ** evaluate the expression
  new identifier3 := function_name(); ** function call
  new identifier4 := variable;        ** object: share the reference
  new identifier5 := native_var;      ** native value: copy the value
  ...

To copy an object with all its attributes, use the clone operator ::. After cloning, changing the copy does not change the original. Cloning applies to objects and collections; native values are always copied. There is no clone keyword or method: :: is the only way to clone. A slice follows the same rule: := creates a view over the elements of the base collection, :: creates a new collection with a copy of them.

  ** making a clone
  new object :: original;
  expect object is not original;

Note: is compares locations, so on native values it is always false, even when the values are equal. Compare native values with ==. On objects, == is a deep comparison: it is True when all attributes or elements are equal.

Ternary Expression

The conditional expression uses if and else instead of ? and :, which have other uses in Eve. The same if keyword starts a conditional statement.

** ternary expression
process main is
  ** on one line:
  new variable1 := (value1 if condition else value2);

  ** on several lines:
  new variable2 := (value1 if condition1 else
                    value2 if condition2 else
                    value3);
  ...
return;

A ternary expression can be an argument:

process
  ** create a logic variable
  new test := True;
  ...
  expect (True if test else False); ** passes
  ...
return;

Statements

A statement is declarative or imperative; Eve uses both kinds.

  • A statement is usually one line of code.
  • A statement can span several lines; it always ends with ;.
  • A group of statements is a block, indented by the same number of spaces.
  • A block ends with its terminator: return, end, done or repeat (see Control Flow).

Single-Line Statements

The next example has five single-line statements, each starting with a keyword: new declares, let modifies, expect verifies. The header line is a declaration, and the final return ends that declaration.

driver assign_demo is
  process main is
    ** initialization statements
    new a := 2;
    new b := 0.0;

    ** evaluate an expression
    let b := a + 0.5;

    ** verification statements
    expect a == 2;
    expect b == 2.5;
  return;
end assign_demo;

Multi-Line Statements

A statement continues on the next line until ;:

  • an expression can continue after an operator;
  • a literal enclosed in parentheses, brackets, braces or quotes can span lines.
** multiple line demo
process main is
  ** multi-line expression
  new var := 1
            + 2
            + 3 + 4 +
              5 + 6;

  ** multi-line literal
  new map := {
      'two' :2,
      'four':4,
      'six' :6
  };
return;

Pitfalls

Identity Versus Equality

is compares locations. On native values it is always false; use == to compare values.

Reference Versus Copy

:= shares the reference of an object, so a change through one variable is visible through the other. Use :: to make an independent copy.

Stars and Comments

** always starts a comment, so 2 ** 3 is 2 followed by a comment. The power operator is ^: 2 ^ 3. Block comments do not nest.
