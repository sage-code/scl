Eve Aspects

An aspect is the one kind of script that runs. It is an encapsulated machine: other aspects call it by its name, its process main is the only way in, and data goes in and out only through the parameters. Any aspect can be run as a driver, or applied by another aspect.

Aspects

An "aspect" is a script that solves a problem or addresses a specific concern of a project. Aspect files are executable. An aspect has declarations and one or more processes. The process main is its entry point: it is public, it receives the parameters of the aspect, and every aspect has one. The other processes of the aspect, if any, are private: only the processes of the same aspect call them, by their bare names.

An aspect is not instantiated and has no public members: the dot operator is never used with an aspect, so worker.ingest(…) is an error. Other aspects write apply worker(10); or start worker(10);, and that runs main. Data goes in by the parameters of main and comes out by its output parameters (@). Each call creates the state of the aspect, and the state is dropped when main returns. The private processes of the aspect work on that same state. An aspect is executed with the keyword apply, in serial mode, or with start in a parallel group. Errors propagate to the caller like in any other process. An error that nobody handles ends the application. The driver captures the exit code of panic, raise, expect and assert.

Aspects are independent of each other. An aspect knows nothing of the other aspects: it sees no variable of the aspect that calls it, it can't call a member of another aspect, and no other script can reach into it. Everything it needs comes through the parameters of main, and everything it produces leaves through its output parameters. This is what lets one aspect compose others freely: an aspect can be tested alone, by running it, and moved to another application without change. Shared code belongs in a module, which every aspect may import.

Calls between aspects:

  • Any aspect may apply or start another aspect, by its name;
  • An aspect can't call itself, and no chain of calls may come back to an aspect already in it: the compiler reports the chain;
  • Calls go at most three levels deep: the aspect that is run, an aspect it calls, and an aspect called from there, which calls no other aspect;
  • Only the call of an aspect makes a level; a call of a private process never does.

Kinds of aspect:

  • exclusive aspect (the default, also written aspect): runs alone, in serial mode. It may use any function and any module;
  • concurrent aspect: may be started in a parallel group. The compiler checks that it uses only what is thread safe;
  • primary aspect: the entry point of an Eve macro, and only of a macro. It is serial like an exclusive aspect, but its parallel groups can start aspects.

Aspect skeleton:


** purpose of the aspect
aspect aspect_name is

  ** declarations of the aspect: private, created at each call
  ** and dropped when main returns; an aspect defines no globals
  new count = 0 :Integer;

  from $path/library_name use (*);

  ** helper work is done by functions
  procedure helper(parameter_list) is
    ...
  return;

  ** a private process: only the processes of this aspect call it
  process prepare(parameter_list) is
    ...
  return;

  ** the entry point: the only public process
  process main(parameter_list) is
    ** executable region
    ...
  recover
    ** handle all errors
    ...
  finalize
    ** release locked resources
    ...
  return;
end aspect_name;

A small application can keep its aspects in one file: an Eve macro. There the aspects also share the declarations at the top of the file, and one of them is the primary aspect, the entry point.
