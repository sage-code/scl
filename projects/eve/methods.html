Eve Methods

A method is a subprogram that does work and can have side effects. It is called as a statement, receives input parameters and gives results back through output parameters marked with @. Functions, shown in the previous chapter, compute a value; methods change things. This chapter shows how to declare and call a method, what side effects are, and how parameters work.

Declaration

Methods are the subprograms that do the work inside a driver or an aspect; they always run in serial mode. In Eve we create a subprogram that can receive parameters and can have side-effects. You can call a method by name, with or without arguments enumerated in a list. A method is created with keyword "method" and is ending with keyword "return". Method do not have to be follow by empty parenthesis when it has no arguments. A method can be declared in a class or at module level, outside any class. A module-level method is public when its name starts with a dot (method .name) and private when it starts with an underscore (method _name). A method can also return a result.

Syntax:


# define a method
method name(parameter_list) is
    ** method statements
    ...
return;

Example

Next example demonstrate two methods: "foo" and "bar". We declare the methods and then call the methods. One of method has no parameters, the other has 3 parameters. Two input and one output parameter.


# demonstrate two methods
driver process_demo is

  ** foo has no parameters
  method foo is
    print "I have no arguments";
  return;

  ** bar has 3 parameters
  method bar(param1:Integer, 
              param2 = 0: Integer,
              @result: Integer) is
    print "I have two parameters: param1 and param2";
    result := param1 + param2;                    
  return;

  process main is
    foo; ** call method without arguments
    let output:=0; ** prepare a variable to receive output

    ** execute method with 2 arguments and receiver
    bar(1, 2, @output);
    expect output == 3; ** the value of output should be 3.
    print ("output=", output);
  return;
end process_demo;

Side Effects

A process can use process states and can have side-effects. When a global state is changed by a method this is called side-effect. This may be useful but potential unsafe. Some side effects may be harder to debug. It is safer to use input/output parameters than side effects.

these are side effects...

  • modify a global variable or system state;
  • open and write into an external file;
  • print a message or accept input from console;
  • upload something on internet or network;

Examples

Next method: "add_numbers" has side effects:


driver side_effect is
  set test   :Integer;
  set p1, p2 :Integer;

  ** method with side effects
  method add_numbers is
    test := p1 + p2; ** first side-effect
    print test;          ** second side-effect
  return;

  ** define main process
  process main is
    p1 := 10;
    let p2 := 20;
    add_numbers; **  method call without arguments
    expect test == 30;
  return;
end side_effect;

Note: In Eve it is not required to use empty parenthesis() to call a method. Only functions require empty brackets. We will talk about functions later. This feature enable us to extend Eve using Eve scripts.

Parameters

Parameters  are defined in round brackets () separated by comma. Each parameter must have type and name. Parameters are optional. Eve offer a range of advanced features: optional arguments, default values, variable number of arguments and input/output arguments.

Parameter Syntax:

Mandatory parameters do not have initial values but only declared type. Optional parameters have initial value that is assign using operator "=" with explicit :type, or ":=" with type inference. Arguments can be pass by position or by name.

  • parameter :Type
  • parameter = value :Type
  • parameter := expression
  • @parameter :Type

A parameter without "@" receives its argument by value, also a collection: the method works on its own copy and the caller's variable does not change. A parameter with "@" is an input/output parameter: it receives a reference to the caller's variable, so the method reads its value and can change it. An "@" parameter can't have a default value, so it is never optional.

Notes:

  1. One method can receive one or more parameters,
  2. Parameters having initial values are optional,
  3. Values used for parameters at runtime, are called "arguments",
  4. You can assign arguments by position using a list of values,
  5. You can assign arguments by name using (name:value) pairs;

Vararg parameters

One method can receive multiple arguments of the same type into a single collection parameter. This can be a List, DataSet or HashMap, depending on declaration.

  • First arguments can be captured using named parameters,
  • The rest of arguments are captured into vararg parameter,
  • A method can have one single vararg parameter,
  • The vararg parameter name is declared using prefix: "*",
  • You can use any name but "*args" is the usual name for it.
Note: Also the process main of a driver or aspect can receive parameters. The same convention apply for aspects, drivers, functions and methods. Eve offer same features for all subprograms. The only difference are the call concentions.

Example:

Next driver can have a list of arguments. The arguments have no names, so it will just print all the arguments it has received. Drivers receive argument values from command line or REPL console using "run" command.

# print all arguments
driver test is

  ** list all arguments
  process main(*args: ()String) is
    loop
      let arg :String;
    for arg in args do
      print arg;  ** expect 1,2,3
    done;
  return;
end test;


eve:>run test.eve 1 2 3

Output Parameters

To avoid overuse of global variables you must use input/output parameters. We prefix output parameters using symbol "@", and the caller writes "@" before the argument too: add(1, 2, @result), or by name add(1, 2, op: @result). The "@" asks for pass by reference; without it the argument is passed by value. An output argument must be a variable, an element or a slice, otherwise you will not be able to capture the output value. The compiler will complain if you do not send a valid reference to an output parameter.


#demo output parameters
driver output_params is

  ** private method
  method add(p1 = 0, p2 = 1: Integer, @op: Integer) is
    op := p1 + p2;
  return;

  process main is
    let result: Integer;

    ** input/output argument requires a reference to a variable
    add(1, 2, op: @result);
    print result;  ** expected value 3

    ** negative tests, will fail
    add(1, 2, result); ** error, "op" requires @
    add(1, 2, @4);     ** error, "op" requires a variable
  return;
end output_params;

Notes:

  • Output parameters are usually the last parameters;
  • Output parameters are having "@" prefix, and so are their arguments;
  • An output parameter has no default value;
  • Method invocation is done using name of method as a statement;
