Eve Objects

Eve is an object oriented language. We define objects and classes. A class is a user defined data type, that encapsulate data structure and methods. An object is an instance of a class. We use classes to create data structures and algorithms.

Objects are state machines that are instantiated on demand and released from memory when they are no longer needed. You can create global objects using "set", or local objects using "let" and the "new" operator, which calls a constructor: let p := new Point(1, 2);.

Using JSON you can create complex data structures of objects. In next example we create a list of objects. Each object can have same structure or different structure. This is possible due to dynamic nature of Objects.

Comparing objects

We can use two comparison operators with objects: "is" and "==". First operator "is" will compare the object memory address. If the objects have the same address they represent the same object. Second operator: "==" compare object type and object attributes. There are complementar operators "is not" and "!=". That can be used to create conditionals.

Class members

A class can have properties and methods. Class properties and metods are static members and must be defined inside the class declaration. Some classes do not have a class declaration body. These classes can have properties defined in the signature between brackets {} but can't have methods.

Class Properties

A class can have properties. We declare class properties after symbol ":" before any class methods in the class body. Class properties are by default private. Public properties are created with "." prefix. Usually a class use private properties, getters and setters if necesary.

  • Properties are defined using keyword "set" ;
  • A class is a singleton Object of type Class;
  • Class properties are visible in all class methods;
  • Public class members start with "." prefix;
  • Private class members start with a lowercase letter;

Class Methods

You can define methods inside of a class body. These are "class methods". Class methods have access to all class members, without using any qualifier but have no access to object instance. @self object is not available in the class methods, unless explicit injected as input/output parameter.:

Object Constructor

You can create more complex objects by using a "constructor". In Eve we name things like they are used in specific programming paradigms. The constructor is a special subprogram that can be used to create a class instance also known as object. A class can be constructor-less in this case you can't create instances of this kind of class.

Design:

Next design pattern explain how to declare a class with attributes and constructor:


# user defined class
class NewType = {attributes} <: Object is
  ** declaration
  ...

  ** constructor is a special subprogram, declared inside the class body
  constructor(@self)([other_parameters]) is
    self := new Object();
    ...
  return;

  ** destructor is symmetric with constructor
  destructor(@self) is
    ** cleanup internal states
    ...
  return;

  ** object method: @self needs no type inside the class
  method attached(@self) is
    ** add extra functionality to the class
    ....
  return;
end NewType;

Notes: A class can have a single constructor, with optional parameters. The constructor and the destructor are declared inside the class body. They look like methods except they use the "constructor" and "destructor" keywords and have no name: the name of the class is known. The first list holds @self, without a type, and the second list holds the parameters that new receives.

Object Methods

A class instance can have attributes and methods. Class instances are objects. Object members are encapsulated in the constructor body. The constructor is declared inside the class body. Object methods are in fact closures and constructor is in fact a higher order function that create @self object.

Parameters

Constructors can have one or more parameters, some may be optonal. It can also have vararg parameters and input/output parameters like any method. You can use a decision statements to initialize the object attributes in different ways based on parameter values.


# define a class
class ClassName = {attributes} <: Object is
   ** define class properties
   set property_name := value;
   ....

   ** define class method
   method .test() => (@result:Type) is
      ...
      result := expression;
   return;

   ** constructor with default and vararg parameter, that is a list of integers
   constructor(@self)(param1:=value1, *param2:()Integer) is
     ** conditional initialization (flexible constructor)
     self := new Object();
     if condition do
       let self.attribute = value;
       ...
     else
       self.attribute = other_value;
       ...
     done;
   return;
end ClassName;

@self object

Object named "self" is the current object name. This is the result of the constructor. It uses prefix "@" to show that it is a reference. The "self". In Eve you must declare @self explicitly, as the first parameter of the constructor, without a type (it is always an object of the class); it represents a pointer to the new object. The constructor assigns it first, with the constructor of the superclass: self := new Object();. The other parameters receive the arguments of new.

Object Attributes

A class can define attributes, with types in the class signature. The class constructor will set initial values for the object attributes just created, and can create additional attributes explicit in the constructor using "let" statement.

  • We declare public attributes using = {...} or += {...n} after class name;
  • Public members are declared in the class body with the prefix ".";
  • Object attributes are private and are created with "let self.name" in the constructor;
  • There is no need to use (.) prefix when declare attributes.

To access public attributes you must use dot notation: 

object_instance.public_attribute;

To access private attributes you must use "self." qualifier available in constructor. Private attributes are available in constructor and methods but are not available with object name as qualifier. That is, private attributes are protected so that developer will not modify them by mistake from outside.

self.private_attribute;

Note A class body does not know anything about its objects or object attributes. You can not ask the class anything about its instances, except if you create a special logic using class properties. Also, class methods, do not receive @self parameter so there is no way to access by mistake an attribute in a class method.

Example:

This example defines a "Point" class with two parameters. The parameters have default values so they are optional when you create a point. Read the example and the notes to understand how to use a user defined class constructor.


# define a "Point" class with a constructor:
driver test_point is

** declare a class "Point"
class Point = {x, y :Real} <: Object is
  ** class method to calculate distance between two points
  method .distance(p1, p2: Point) => (@result: Real) is
    let dx := p2.x - p1.x;
    let dy := p2.y - p1.y;
    result := sqrt(dx*dx + dy*dy);
  return;

  ** primary constructor: @self first, then the parameters
  constructor(@self)(x = 0, y = 0 :Real) is
    self := new Object();
    let self.x := x;
    let self.y := y;

    ** instance method to move the point
    method move(a, b: Real) is
      self.x += a;
      self.y += b;
    return;

    ** instance method to convert point to string
    method string() => (string:String) is
      string := "(#:#)" ? (self.x, self.y);
    return;
  return;
end Point;

process main is
    ** use the constructor with different arguments
    let p1 := new Point(1, 2);        ** two-parameter constructor
    let p2 := new Point();            ** no-parameter constructor (uses defaults)
    let p3 := new Point(p1.x, p1.y);  ** copy the values of p1

    ** print results
    print "p1: #" ? p1.string();
    print "p2: #" ? p2.string();
    print "p3: #" ? p3.string();

    ** demonstrate distance calculation
    let distance := Point.distance(p1, p3);
    print "Distance between p1 and p3: #" ? distance;
return;
end test_point;

Output:

p1 = {x:1, y:2}
p2 = {x:2, y:2}

Example:

This example defines a class that can track its instances explicit. You can use static properties of a class to record all instances newly created. In the destructor, you can remove the object instance self from the item list.


# demonstrate a self tracking class
driver self_track is

** define class Point, from root Object
class Point = {x, y :Real} <: Object is
  ** tracking information (private class properties)
  set instances: Integer;
  set items: ()Point;  ** list of points

  ** constructor receive 2 parameters
  constructor(@self)(x = 0, y = 0 :Real) is
    ** alter attribute values
    self := new Object();
    let self.x := x;
    let self.y := y;
    ** add object to list of items
    items += self;
    instances += 1;
  return;

  destructor(@self) is
    ** remove the object from list
    items -= self;
    instances -= 1;
  return;
end Point;

process main is
  ** initialize the points
  let p1 := new Point(x:1, y:2);
  let p2 := new Point(x:2, y:2);

  ** verify how many point
  expect Point.instances == 2;

  ** use item list to print all points
  loop
    let i := 0;
  for p in Point.items do
    i += 1;
    print "p#n = (x:#n, y:#n)" ? (i, p.x,p.y);
  done;
return;
end self_track;

Output:

p1 = {x:1, y:2}
p2 = {x:2, y:2}

Inheritance

Eve support multiple inheritance and polymorphism. You can specify one or more supertypes after the inheritance operator in a list. This is the "inheritance" symbol. It can define a new class that inherite all attributes and methods of the super-classes or bas-class.

Pattern:


** define a BaseType for inheritance without a superclass
class BaseType = {attribute};

** define an abstract class without attributes
class AbstractType <: Object is
  ** abstract method to be implemented
  method demo(parameters) => (result:Type);
end AbstractType;

** create a descendent of BaseType and AbstractType
class NewType += {new_attribute} <: (AbstractType, BaseType) is
  ** class members
  ...
  ** implement abstract method
  method demo(parameters) => (result:Type) is
    ...
  return;

  ** constructor for the new class
  constructor(@self)(param1, param2) is
    ** initialize object Attributes
    self := new Object();
    let self.attribute := param1; ** object attribute
    let self.new_attribute := param2; ** dynamic private attribute
    ...
  return;
end NewType;

Partials, Abstract Classes and Traits

A partial method is a method signature without a body, ended by ;. It says what an object can do, and leaves the implementation to another class. Three entities use partial methods. Each has a different job, so Eve names them separately:

EntityStateMethodsCreated with "new"
Classattributes and constructorall implementedyes
Abstract classattributes and constructorsome partialno, only a subclass constructor calls it
Traitnonepartial and providedno, never has instances

Abstract Class

A class that has at least one partial method is an abstract class. It can have attributes, a constructor and implemented methods, like any class, but it can not be instantiated. A subclass calls the abstract constructor by the name of the class, in its own constructor. Inside a class body, object methods take @self without a type.


** abstract class: it has partial methods
class Shape = {name: String} <: Object is
    constructor(@self)(name: String) is
        self := new Object();
        let self.name := name;
    return;

    ** implemented method, inherited by all shapes
    method getName(@self) => (@result: String) is
        result := self.name;
    return;

    ** partial methods: the subclass must implement them
    method area(@self) => (@result: Real);
    method perimeter(@self) => (@result: Real);
end Shape;

class Circle = {radius: Real} <: Shape is
    constructor(@self)(name: String, radius: Real) is
        self := new Shape(name);  ** call the abstract constructor
        let self.radius := radius;
    return;

    method area(@self) => (@result: Real) is
        result := pi * self.radius * self.radius;
    return;

    method perimeter(@self) => (@result: Real) is
        result := 2 * pi * self.radius;
    return;
end Circle;

# Usage
process main is
    let myCircle := new Circle("Small Circle", 5);
    print myCircle.getName();  ** inherited from Shape
    print myCircle.area();     ** implemented by Circle
return;

A class that has a constructor must implement all the partial methods it inherits. A missing implementation is a compile error. It is never a Null result at run time.

Traits

A trait is a set of behaviors that unrelated classes can share. It is declared with the keyword trait, and it closes with end. A trait is a container of methods only:

  • it has no attributes, no properties, no constructor and no destructor, so it has no state and no instances;
  • a required method is a partial method: the class that adopts the trait must implement it;
  • a provided method has a body. It can call the required methods through @self, and the class receives it for free;
  • @self has no type: it is the class that adopts the trait;
  • a trait can be generic: trait Comparable(:T) is.

** a trait: one required method and one provided method
trait Printable is
    method toString(@self) => (@result: String);

    method show(@self) is
        print self.toString();
    return;
end Printable;

** a class adopts traits in the inheritance list
class Circle = {radius: Real} <: (Shape, Printable) is
    constructor(@self)(name: String, radius: Real) is
        self := new Shape(name);
        let self.radius := radius;
    return;

    ** implement the required methods of Shape and Printable
    method area(@self) => (@result: Real) is
        result := pi * self.radius * self.radius;
    return;

    method perimeter(@self) => (@result: Real) is
        result := 2 * pi * self.radius;
    return;

    method toString(@self) => (@result: String) is
        result := "Circle '#' with radius #" ? (self.getName(), self.radius);
    return;
end Circle;

# Usage
process main is
    let myCircle := new Circle("Small Circle", 5);
    myCircle.show();                   ** provided by the trait
    let p: Printable := myCircle;      ** a trait is also a type
    p.show();
    expect myCircle is Printable;
return;

Rules of the inheritance list

  • A class has at most one superclass that carries state, and any number of traits. The superclass is optional (Object by default);
  • when a class and a trait define the same method, the method of the class wins;
  • when two traits provide the same method, the class must implement the method itself, otherwise the compiler reports an error;
  • a trait can be used as the type of a variable or a parameter, and tested with is;
  • the for loop uses the library trait Iterable: a class that adopts it can be traversed.

Note: Eve has no "partial constructor". An object receives its state from the constructor of a class, and the traits add behavior only. This is why a class never inherits conflicting attributes from two parents.

Generics in Eve

Eve supports generics, allowing for the creation of flexible, reusable code structures that can work with different types while maintaining type safety. Generics are used in Eve system libraries. You can create sub-types using a generic. Next generics are pre-defined: {Array, List, DataSet, HashMap}. We will describe these data types in next chapter.

Generic Syntax

The basic syntax for defining a generic class in Eve is as follows:


class GenericClass(:T) <: SupetType is
    ** Generic method
    method genericMethod(value: T) => (@result: T) is
        ** Implementation
    return;
end GenericClass;

In this syntax:

  • (:T) is a type parameter. It can be any valid identifier.
  • You can use T as a type within the class definition.
  • When instantiating the class, you specify the actual type:
    let instance := new GenericClass(:Integer)(constructor_arguments);

Optional Type

Eve provides an Optional type, which is a variant that can be either a value of a specific type or Null. This is particularly useful for handling nullable values in a type-safe manner.

Example: Using Optional with Generics

Here's an example demonstrating the use of Optional with a generic class:


# Define an Optional type
class Optional(:T) = {T | Null} <: Variant;

# Define a generic processor class using Optional
class Processor(:T) is
    method process(value: Optional(:T)) => (@result: Optional(:T)) is
        if value is Null do
            result := Null;
        else
            ** Type-specific processing
            if type(value) is Integer do
                result := value + 1;
            else if type(value) is String do
                result := value + " processed";
            else
                result := value;  ** Default case
            done;
        done;
    return;
end Processor;

# Usage example
driver test_optional_processor is
    ** Create processor instances
    let intProcessor := new Processor(:Integer);
    let stringProcessor := new Processor(:String);

    process main is
        ** Test with non-null values
        let intResult := intProcessor.process(:Integer,5));
        print intResult;  ** Output: Optional(6)

        let stringResult := stringProcessor.process(Optional(:String)("Hello"));
        print stringResult;  ** Output: Optional("Hello processed")

        ** Test with Null
        let nullResult := intProcessor.process(Null);
        print nullResult;  ** Output: Null
    return;
end test_optional_processor;

This example demonstrates how to use generics with the Optional type to create flexible, type-safe code that can handle nullable values elegantly.

Generic constructor

The syntax for the generic constructor follows the same pattern as the class. We use special notation (:T) to receive the type, then use the type inside the constructor body and in the parameter list. The type list (:T) belongs to the class. The constructor has no name: it has two lists, (@self) and the parameters, and it is called with the same lists: new Number(:i32)(42).


  # Generic Number class that can work with different integer types
  class Number(:T) <: Object is
      set value: T;

      # Generic constructor: @self first, then the parameters
      constructor(@self)(initialValue: T) is
          self := new Object();
          let self.value := initialValue;

          # Method to get the value
          method getValue() => (@result: T) is
              result := self.value;
          return;

          # Method to set the value
          method setValue(newValue: T) is
              self.value := newValue;
          return;

          # Method to add to the value
          method add(addend: T) is
              self.value += addend;
          return;

          # Method to multiply the value
          method multiply(factor: T) is
              self.value *= factor;
          return;

          # Method to print the value
          method print() is
              print "Number value: #" ? self.value;
          return;
      return;
  end Number;

  # Usage example
  driver test_generic_number is
      process main is
          # Create a Number with i32
          let num32 := new Number(:i32)(42);
          num32.print();  # Output: Number value: 42

          # Create a Number with i64
          let num64 := new Number(:i64)(9223372036854775807);  # Max value for i64
          num64.print();  # Output: Number value: 9223372036854775807

          # Use the methods
          num32.add(10);
          expect num32.getValue() == 52;

          num64.multiply(2);
          expect num64.getValue() == 18446744073709551614;

          # Test with Integer (boxed i64)
          let numInteger := new Number(:Integer)(1000);
          numInteger.print();  # Output: Number value: 1000
          numInteger.add(500);
          expect numInteger.getValue() == 1500;
      return;
  end test_generic_number;

Method Chaining in Eve

Method chaining is an advanced programming technique available in Eve that allows developers to call multiple methods on the same object in a single statement. This can lead to more concise and readable code, especially when performing a series of operations on an object.

Note: Method chaining is an optional feature in Eve. Developers can choose whether to implement it based on their specific needs and coding style preferences.

How Method Chaining Works

In method chaining, each method in the chain returns the object instance (usually referred to as @self in Eve) after performing its operation. This allows the next method in the chain to be called on the same object.

Example of Method Chaining


class Number(:T) <: Object is
    set value: T;

    constructor(@self)(initialValue: T) is
        self := new Object();
        let self.value := initialValue;

        method add(addend: T) => (@self) is
            self.value += addend;
        return @self;

        method multiply(factor: T) => (@self) is
            self.value *= factor;
        return @self;

        method print() => (@self) is
            print "Number value: #" ? self.value;
        return @self;
    return;
end Number;

# Usage
process
    let num := new Number(:i32)(10);
    num.add(5).multiply(2).print();
return;

Benefits of Method Chaining

  • More concise code
  • Improved readability for sequences of operations
  • Fluent interface design

Considerations

While method chaining can lead to more elegant code, it's important to use it judiciously. Very long chains can sometimes become difficult to read or debug. Developers should balance the benefits of conciseness with overall code clarity.

Best Practice: Consider breaking very long chains into multiple statements or using intermediate variables for better readability and easier debugging.

Implementing Method Chaining

To implement method chaining in Eve, developers need to:

  1. Modify method signatures to return @self
  2. Return @self at the end of each chainable method
  3. Ensure that the method performs its operation before returning

Remember, implementing method chaining is optional in Eve. Developers can choose to use traditional method calls if they prefer, or mix chained and non-chained methods as appropriate for their code structure.
