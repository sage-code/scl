Eve Asynchronous Functions

An asynchronous function does not make the caller wait for its result: the caller goes on, and takes the result later, when it needs it. Many languages mark such a function with async and wait with await. Eve has a different answer: the code stays sequential, and the machine overlaps the waiting. This page explains how, and lists what is still open.
Not in Eve 0.1. Parallel groups, channels and generators are designed for later versions. The keywords async, await and suspend are not used in Eve (D-051, D-067).

Waiting gives the core away

An aspect that waits for a file, the network, a database, a wait 10ms; or a channel releases its worker core to another task and continues when the wait is over. The code does not change: it reads like code that waits. There is no second kind of function, and no function "colored" by async that can be called only from another one.

Several things at once: start

To do several slow things at the same time, the driver starts several aspects in a parallel group. Each aspect is the "asynchronous function"; done is the "await".


# call 50 services at the same time
driver fetch_all is
  process main is
    new answers: [50]String;

    parallel
    do
      for i in (1..50) do
        start fetch(i, @answers[i]);   ** each call waits for its own service
      done;
    done;                              ** all answers are ready here

    print answers[1];
  return;
end fetch_all;

Callbacks and completion

A callback (Callbacks) runs in serial mode, in the receiver. It is not called "later, from another thread": that would bring data races into plain code. When a result arrives from a parallel task, the driver reads it after done, or receives it from a channel.
