Eve Asynchronous Functions

An asynchronous function or procedure lets its caller go on while it waits for a file, the network or a database. Eve marks such a subprogram with async. Inside a job, spawn starts it as a task and the job goes on; await starts it and waits for it at once, in serial mode. The machine overlaps the waiting of the tasks of a job on one core.

Waiting gives the core away

A task or an aspect that waits for a file, the network, a database, a wait 10ms; or a channel releases its core to another task and continues when the wait is over. The code does not change: it reads like code that waits.

Asynchronous functions and procedures

The keyword async in front of function or procedure declares a subprogram that can be run as a task:


async procedure name(parameters) is
  ...
return;

async function name(parameters) => (@result: Type) is
  ...
return;

A job is split into tasks. spawn starts an asynchronous subprogram as a task: the job does not wait for it and the next statement runs at once. await starts one and waits at once until it has finished, in serial mode. All the tasks of one job share one core, the core of the job: a task works until it has to wait, then gives the core to the next one. The closer of the job, done name;, waits until every task spawned in the job has finished.


# read three files at the same time, on one core
driver load_all is

  ** an asynchronous procedure: no result, the text goes out by @text
  async procedure load(path: String, @text: String) is
    new f := fs.open(path);
    defer f.close();
    let text := f.read();   ** waits for the disk: the core goes to the next task
  return;

  process main is
    new a, b, c :String;
    loading: job
    do
      spawn load("one.csv", @a);     ** a task: the job goes on
      spawn load("two.csv", @b);     ** a second task
      await load("three.csv", @c);   ** starts and waits for this one
    done loading;                    ** waits for every spawned task
    print a.length(), b.length(), c.length();
  return;
end load_all;

Rules

  • async marks a function or a procedure that runs as a task;
  • spawn starts a task in a job of a driver or of an aspect and goes on; await starts it and waits for it, in serial mode;
  • Inputs are passed by value; the outputs of a procedure are @ parameters, ready after the done of the job (after the await for an awaited task);
  • The tasks of one job run on the same core, one at a time: there is no data race between them, and no lock is needed;
  • To use several cores, start aspects in a parallel group (next section): start is for aspects, spawn for tasks.

Several cores: parallel

To do several slow things at the same time on several cores, the driver starts several aspects in a parallel group. Each aspect runs on its own core; done is the "await".


# call 50 services at the same time
driver fetch_all is
  process main is
    new answers: [50]String;

    parallel
    do
      for i in (1..50) do
        start fetch(i, @answers[i]);   ** each call waits for its own service
      done;
    done;                              ** all answers are ready here

    print answers[1];
  return;
end fetch_all;

Callbacks and completion

A callback (Callbacks) runs in serial mode, in the receiver. It is not called "later, from another thread": that would bring data races into plain code. When a result arrives from a parallel task, the driver reads it after done, or receives it from a channel.
