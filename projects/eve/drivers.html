Eve Drivers

A driver is the aspect that runs first: the entry point of an application. Eve has no driver keyword: any aspect can be a driver, depending on which aspect you run. This page describes the role and how a run goes. The shape that all scripts share is on the Scripts page.

Drivers

A driver is a role, not a kind of script. The aspect that the machine runs first is the driver of that run: it leads the main process of the application and calls the other aspects. When its main returns, the application gives control back to the Eve virtual machine. If no other process is running, the machine shuts down after it cleans up the memory.

Notes:

  • Any aspect can be a driver: eve report.eve runs the aspect report and makes it the driver of the run;
  • An application can have several drivers: each one is an aspect that you run, a different use case of the same aspects and modules;
  • A driver can read configuration files at startup;
  • The process main of the driver receives the command-line arguments as its parameters;
  • The state of the driver is the scope of the run: the modules it imports are bound to it;
  • An aspect is never imported; only a module is;
  • In an Eve macro, the driver is the one aspect marked primary.

Driver Execution

When an aspect is run, the aspects it calls are found and compiled in memory with it, then its main process is executed. The aspect it applies runs its own process main. Calls go at most three levels deep: the driver, an aspect it calls, and an aspect called from there. An aspect can't call itself, and no chain of calls may come back to an aspect already in it; the compiler reports such a chain as an error.

The console REPL (parse, debug and execute a script step by step) and the daemon mode are planned for a later version. They describe the tool, not the language, so they are documented in the manual of the implementation: manual/usage.md in the eve-lang repository.

Example: a driver applies an aspect

The aspect is in its own file, print_this.eve. The aspect greeting is the one that is run, so it is the driver: it decides when the other aspect runs and what it receives.


# the aspect: it receives a parameter and prints it
exclusive aspect print_this is
  process main(p: String) is
    print p;
  return;
end print_this;


# the driver: the aspect that is run, the entry point of the application
aspect greeting is
  process main is
    apply print_this("Hello");        ** serial mode: the driver waits
    apply print_this("Goodbye");
  return;
end greeting;

Both files are aspects. Run eve greeting.eve and greeting is the driver; run eve print_this.eve Hi and print_this is the driver, alone. An aspect is never imported.
