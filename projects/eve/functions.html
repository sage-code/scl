Eve Functions

A function is a relation between input and output values. A function makes a computation to establish the output. Eve functions are objects of type Function. Eve enable functional programming paradigm (FP). Functions are the main subprograms of Eve. A subprogram that does not belong to a class is a function when it returns a result, and a procedure when it only does work and returns nothing, like print. The two words come from Ada. Methods belong to classes (see Methods).

The keywords that phase 3, Functional Programming, adds to the core language (the core keywords are in Syntax). Each one is explained on the page in the last column.

Function declaration

Functions are declared with keyword: "function", procedures with keyword: "procedure". A function always has a result; a procedure never has one. A module exports the functions and procedures other scripts may use (export (…), see Modules); a driver or an aspect uses its own.

Pattern:

#function declaration
function name(parameters) => (@result:TypeName) is
  ** executable block
  ...
return;

#procedure: no result, it does work
procedure name(parameters) is
  ...
return;

Two kinds of functions, and procedures

KindDeclaredCalledParallel
Plain function: a result, no side effects, deterministicfunction area(r: Real) => (@a: Real) isin an expression: area(2)the compiler decides (see Thread safety)
Stochastic function: a result that can differ for the same arguments (random, time, a changing module variable, a counting closure); it changes nothingfunction next!() => (@n: Integer) isin an expression: next!()the compiler decides (see Thread safety)

Notes:

  • A function always has a result and is used in expressions. A subprogram without a result is a procedure: it is a statement and needs no !, even when it has side effects (see Procedures). function without a result list, or procedure with one, is a compile error,
  • Result type is declared using prefix @. The prefix forces a reference: new v := f(x); is valid because v is a variable, 2 := f(x); is not,
  • A function can return a list of results => (@r1:Type, @r2:Type). In this case $result is a list (result1, result2),
  • A procedure can have input/output parameters (@) and change them; a function changes nothing, also not its parameters,
  • A function can receive parameters of type function,
  • A function can create a function enclosed in it, called closure,
  • A function has a name: the keyword function must be followed by an identifier. A lambda expression is a notation that creates a function in a single statement,
  • A function can raise errors but it can't handle errors. Only a process can handle errors, so use preconditions to avoid runtime errors,
  • A function has no state between two calls; a closure keeps the state of the function that created it,
  • A function returns a result and changes nothing; a procedure changes something and returns nothing (command–query separation). A plain function is also deterministic: the same arguments always give the same result. A function whose result can differ for the same arguments is stochastic; its name ends with !: name!(). ! means only that: it says nothing about thread safety. The compiler decides for every function whether it is thread safe, deterministic or not (see Thread safety).

Execute function Function is executed in expressions using the name of the function followed by the list of arguments in round brackets (). Brackets are mandatory even if there are no arguments.

Function arguments The arguments can be pass by position or by name. Positional arguments go first; mandatory parameters do not require a name. Optional parameters require naming.

Pattern:


#demo function execution
driver function_ex is

  ** declare functions
  function name1(param :Type,...) => (@result:Type) is
    let result := expression;
  return;

  function name2(param = value,...) => (@result:Type) is
    let result := expression;
  return;

  process main is
    ** execute using argument list
    new result1 := name1(arguments);

    ** execute using parameter names with pair operator (:)
    new result2 := name2(param:arg,....);
  return;
end function_ex;

Note: Argument value can be an expression or a variable that translate to a value of expected type. For clarity of application we encourage creation of local variables for arguments.

  • value ::= constant | variable
  • value ::= expression | other function call

Formal parameters

  • Parameters are declared in parenthesis () after the function name,
  • Each parameter has name and type and can have one default value,
  • When a function is called each parameter receive an argument.

Function arguments

There is a difference between the parameter and the argument. The parameter is a local variable in the function scope while arguments are values assigned to these parameters in a function call. Arguments can be literals, constants, variables or expressions.

Example:

# demo function with parameters
driver function_params is

  function sum(a, b: Integer) => (@result:Integer) is
    let result := (a + b);
  return;

  process main is
    print sum(1,2);  ** 3
    print sum(2,4);  ** 6
  return;
end function_params;

Calling a function

A function is called by its name followed by the arguments in round brackets. The brackets are mandatory, also when there are no arguments.

Two ways to call

  • In an expression, when the function has a result: new a := area(2);, print area(2) + 1;, or as an argument of another call: print area(sum(1, 2));;
  • As a statement, when it is a procedure: log("start");. A function called as a statement is not an error, but its value is lost, and the compiler warns.

Positional and named arguments


function box(width: Integer, height = 1, depth = 1: Integer) => (@v: Integer) is
  let v := width * height * depth;
return;

print box(2);                  ** 2: height and depth have defaults
print box(2, 3);               ** 6
print box(2, depth: 4);        ** 8: an optional parameter is given by name

The positional arguments go first, in the order of the parameters. A parameter with a default value is optional and is given by name (name: value). More about parameters is in the section Parameters.

Recursion

A function can call itself. Every call has its own parameters and local variables. A recursive function has a case that ends the recursion; without it the calls never stop and the process ends with the unexpected-stop code (recursion too deep).


function factorial(n: Integer) => (@r: Integer) is
  if n <= 1 do
    let r := 1;                          ** the case that ends the recursion
  else
    let r := n * factorial(n - 1);       ** the function calls itself
  done;
return;

Functions can be recursive; processes can not (see Aspects).

Anonymous and self-calling functions

A function with no name is a lambda expression (Expressions). An anonymous self-calling function is a lambda that is created and called in the same place: the value of the whole expression is the result of the call. It is useful to compute a value that needs a few steps, without leaving a name behind.


** create and call at once: the lambda in brackets, then its arguments
new area := ((r: Real) => (3.14159 * r * r))(2.0);     ** 12.56636

** the same with two results
new (lo, hi) := ((a, b: Integer) => (min(a, b), max(a, b)))(7, 3);   ** 3, 7
  • The lambda is in brackets, followed by the argument list in brackets: (lambda)(arguments);
  • It follows the rules of a lambda: expressions only, no state;
  • For more than one expression of work, write a named function: it can be tested and reused.

An anonymous function can't call itself: it has no name for the call, and Eve gives it none. A recursive function is written as a named function (factorial above).

Because (…)(…) is the call of an anonymous function, a function never has two parameter lists. A function with optional parameters takes them by name at the call: greet("Eve", greeting: "Hi") (see Positional and named arguments).

Procedures

A procedure is a subprogram without a result, declared with the keyword procedure, as in Ada. It does work: it prints, writes a file, changes its @ parameters or the state of a module. It is called as a statement, by its name, and the parentheses can be left out when it has no arguments. It has no !: a procedure is expected to have side effects, otherwise it would be useless. print, write and read of the system library are procedures.

  • A procedure is never deterministic: it is made for side effects, so it never ends with !; procedure p!() is a compile error;
  • Eve holds no references to procedures: a procedure is not a value, it can't be passed as a callback, stored or returned, and there are no procedure types;
  • A procedure can create closures and give them out through @ output parameters; the closures are functions (see Closures).

These are side effects:

  • modify a global variable, a module variable or the system state;
  • open and write into an external file;
  • print a message or accept input from console;
  • upload something on internet or network.

It is safer to use input/output parameters than side effects. A procedure that changes state shared between threads must protect it with an atomic variable or a mutex; the compiler checks it, and rejects an aspect that calls a function that is not thread safe (see Thread safety).

Example


# procedures
driver process_demo is
  new total = 0 :Integer;

  ** foo has no parameters
  procedure foo is
    print "I have no arguments";
  return;

  ** add has a side effect: it changes the global total
  procedure add(value: Integer) is
    let total += value;
    print "total is now {total}";
  return;

  process main is
    foo;          ** called without parentheses: no arguments
    add(10);
    add(20);
    expect total == 30;
  return;
end process_demo;

Parameters

Parameters  are defined in round brackets () separated by comma. Each parameter must have type and name. Parameters are optional. Eve offer a range of advanced features: optional arguments, default values, variable number of arguments and input/output arguments. The same rules hold for functions, methods, generators and processes.

Parameter Syntax:

Mandatory parameters do not have initial values but only declared type. Optional parameters have initial value that is assign using operator "=" with explicit :type, or ":=" with type inference. Arguments can be pass by position or by name.

  • parameter :Type
  • parameter = value :Type
  • parameter := expression
  • @parameter :Type

A parameter without "@" receives its argument by value, also a collection: the function works on its own copy and the caller's variable does not change. A parameter with "@" is an input/output parameter: it receives a reference to the caller's variable, so the subprogram reads its value, and a procedure can change it. An "@" parameter can't have a default value, so it is never optional.

Vararg parameters

One function can receive multiple arguments of the same type into a single collection parameter. This can be a List, DataSet or DataMap, depending on declaration.

  • First arguments can be captured using named parameters,
  • The rest of arguments are captured into vararg parameter,
  • A function can have one single vararg parameter,
  • The vararg parameter name is declared using prefix: "*",
  • You can use any name but "*args" is the usual name for it.
Note: Also the process main of a driver or aspect can receive parameters, with the same conventions. Eve offer same features for all subprograms. The only difference are the call conventions.
# print all arguments
driver test is
  process main(*args: ()String) is
    for arg in args do
      print arg;  ** expect 1,2,3
    done;
  return;
end test;

eve -x test.eve 1 2 3

Output Parameters

To avoid overuse of global variables use input/output parameters. We prefix output parameters using symbol "@", and the caller writes "@" before the argument too: add(1, 2, @result), or by name add(1, 2, op: @result). The "@" asks for pass by reference; without it the argument is passed by value. An output argument must be a variable, an element or a slice. The compiler complains if you do not send a valid reference to an output parameter.


#demo output parameters
driver output_params is

  ** a procedure gives its output through @op
  procedure add(p1 = 0, p2 = 1: Integer, @op: Integer) is
    let op := p1 + p2;
  return;

  process main is
    new result: Integer;

    ** input/output argument requires a reference to a variable
    add(1, 2, op: @result);
    print result;  ** expected value 3

    ** negative tests, will fail
    add(1, 2, result); ** error, "op" requires @
    add(1, 2, @4);     ** error, "op" requires a variable
  return;
end output_params;

Notes:

  • Output parameters are usually the last parameters;
  • Output parameters are having "@" prefix, and so are their arguments;
  • An output parameter has no default value.

Functional programming in Eve

Functions are the first of six pages of this phase:

  • Generators: functions that give values one at a time;
  • Closures: functions created by functions, with a state;
  • Lambda Expressions: functions written as expressions;
  • Callbacks: functions passed to other code;
  • Asynchronous Functions: async, spawn and await, tasks of a job, parallel groups.
