Exceptions

This page summarizes the design of the exception library: the types, the system variables and the predefined constants. The tables list every standard error and warning, with its code and the pattern of its message. The statements that raise and handle exceptions are explained in Processing.
Draft: the codes and the message patterns below are proposed. The forms of raise and the Exception module are not final (PRC-08, PRC-09).

Library Design

The exception module belongs to the standard library: it is imported by default. It is written in Eve. A process that cannot continue raises an error; the workflow jumps into the recover region, where the developer reads $error. A warning does not interrupt the process: it is added to $trace and the process goes on. Warnings are reported in the final exit status of the driver.

The class Error in the module Exception:

** system exception type
module exception is

  ** an error: its code is also the exit code
  class .Error = {code: Integer, message: String, module: String, line: Integer, job: String} <: Object is
    constructor(@self)(code = 4, message = "" :String) is
      self := new Object();
      let self.code := code;
      let self.message := message;
    return;
  end Error;

end exception;

Signatures

Only the signatures are given. A declaration with the keyword external keeps only the signature: it is implemented in Zig by the virtual machine. The source of the module is evevm/lib/exception.eve. An exception is an object {code: x, message: y}; raise is overloaded and accepts a constructor call, a code constant with a message, a code with a message, an exception object, or only a message (code 4).

** raise an exception object
external .raise(e: Error);

** raise an error with a code and a message
external .raise(code: Integer, message: String);

** raise an error with the default code 4
external .raise(message: String);

** raise $err_expect when the condition is false
external .expect(condition: Logic, message := "");

** report a warning when the condition is false
external .assert(condition: Logic, message := "");

** report a warning and go on
external .warn(code: Integer, message: String);

Predefined Constants

Every standard error and warning has a predefined constant: $err_name for an exception and $wrn_name for a warning. The constant is the integer code. In the recover region you compare it with the code of the error:

recover
  if $error.code == $err_file do
    print "Skip the missing file: " / $error.message;
    resume;
  else
    abort;
  done;

The constants are read only. The exit code of a driver that ends with an unhandled error is the code of the error (see Topology).

Code Ranges

CodesUse
1 to 9The statements of the language: panic 1, expect 2, assert 3 (a warning), raise 4 by default, then warnings.

128 to 255Errors defined by a project. Keep the codes of a project unique.
