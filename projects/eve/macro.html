Eve Macros

An Eve macro is a file that holds several aspects and the declarations they share, with one primary aspect as the entry point. A small application, also a parallel one, needs no project folder. Macros are the home of demos and tests.

One file, several aspects

A project spreads its work over many files: the aspects at the root and in asp/, the modules in lib/ (see Scripts). This is the right shape for a large application, but it is heavy for a small one. A job that runs two workers in parallel, a demo or a test should fit in one file that you can copy, mail or run with one command. A file with one aspect is already the shortest program (Running an aspect); when the program needs more aspects, they go in the same file and the file is a macro:

Both are self-contained: nothing in them can be imported by another script, so they never become a hidden dependency. Code that several programs need belongs in a module.

Eve macro

An Eve macro is one file that holds shared declarations and any number of aspects, exactly one of them a primary aspect. The primary aspect is the entry point of the macro: primary is written in front of aspect, in the place of exclusive or concurrent; it is the same kind of aspect as in a project. The declarations are written at column 1, in any order; by custom the shared declarations come first, then the other aspects, and the primary aspect last, so the file reads from the tools to the work.


# score: a primary aspect and its aspect in one file

** shared declarations: seen by all the aspects
set bonus = 5 :Integer;
new total := 0;

function twice(x: Integer) => (@result: Integer) is
  let result := x * 2;
return;

** an exclusive aspect runs alone, so it may change a shared variable
exclusive aspect collect is
  process main(points: ()Integer) is
    for p in points do
      let total += p + bonus;
    done;
  return;
end collect;

** the primary aspect: process main is the entry point of the macro
primary aspect score is
  process main is
    apply collect((10, 20));
    apply collect((30, 40));
    print "total: {total}";        ** total: 120
    print "double: {twice(total)}"; ** double: 240
  return;
end score;

Shared declarations

Every top-level declaration that is not an aspect is shared by the whole file: classes, functions, procedures, methods, constants (set), variables (new) and imports (from … use). This is the difference from a project, where an aspect sees nothing of the aspect that calls it: in a macro the aspects share what the file declares at the top. Each aspect still keeps its own scope and state, and it sees no variable of another aspect; only the shared declarations are common.

  • The primary aspect and the exclusive aspects use every shared declaration, the variables too: they run alone, so they change a shared variable safely.
  • A concurrent aspect uses only what is thread safe: constants, classes, atomic variables (Atomic(:T)), channels, and the functions and procedures that the compiler proves thread safe. Anything else is a compile error that names it (below).

A parallel job in one file

A macro is the natural home of a small parallel job. The primary aspect is serial, but its parallel groups start the concurrent aspects of the file (see Concurrency); a shared class carries the results back. An output is declared before the group, so it is still there after done.


# pipeline: two workers in parallel, one file

class Result = {name :String, count :Integer} <: Object is
  constructor(name = "" :String, count = 0 :Integer) => (@self) is
    let self := Object();
    let self.name := name;
    let self.count := count;
  return;
end Result;

concurrent aspect job_worker_1 is
  process main(@res: Result) is
    ** internal sequential job logic
    let res := Result("worker 1", 10);
  return;
end job_worker_1;

concurrent aspect job_worker_2 is
  process main(@res: Result) is
    ** internal sequential job logic
    let res := Result("worker 2", 20);
  return;
end job_worker_2;

# the primary aspect: it starts the parallel tasks
primary aspect pipeline is
  process main is
    new r1 := Result();
    new r2 := Result();
    p_exec: parallel
    do
      start job_worker_1(@r1);
      start job_worker_2(@r2);
    done p_exec;
    print "{r1.name}: {r1.count}, {r2.name}: {r2.count}";
  return;
end pipeline;

This example is the demo pipeline_macro; every demo of the tutorial that needs aspects is written as a macro (Demos & Examples).

Concurrent aspects that must add to the same total use a shared atomic variable. Reading it gives a value that depends on the timing of the tasks, so the function that reads it is stochastic and its name ends with !:


# counter: eight tasks add to one shared atomic total
new count = 0 :Atomic(:Integer);

procedure add(n: Integer) is
  let count += n;
return;

function total!() => (@result: Integer) is
  let result := count;
return;

concurrent aspect adder is
  process main(times: Integer) is
    for i in (1..times) do
      add(1);
    done;
  return;
end adder;

primary aspect counter is
  process main is
    parallel
    do
      for i in (1..8) do
        start adder(1000);
      done;
    done;
    print "total: {total!()}";   ** total: 8000, at every run
  return;
end counter;

Rules

  • A macro has exactly one primary aspect; eve file.eve runs its process main, which takes the command-line arguments. It is the root of the run, so no aspect applies or starts it.
  • The primary aspect is serial: its processes are exclusive, applied and never started. Its parallel groups start the concurrent aspects of the macro.
  • primary, exclusive and concurrent are reserved words of the same design. A file with one aspect can be primary too: it is then the shortest program, not a macro.
  • Line 1 is a # title or the code. There is no #! line: Eve is a language for projects, not a shell language.
  • Only declarations at the top level: a statement outside a declaration is an error.
  • The aspects of a macro are private: no other script can apply or start them. A macro exports nothing and can not be imported.
  • An aspect named in apply or start is searched first in the macro, then in asp/ and at the project root. An aspect of the macro with the name of an aspect file of the project is an error, so the reader never wonders which one runs.
  • The calls between the aspects of a macro follow the rules of Aspects: no cycle, and at most three levels deep, counted from the primary aspect.

Which one to choose

A program usually grows in three steps, and each step keeps the code of the one before:

  1. One aspect: a few statements in process main to try an idea or to do a small job.
  2. Eve macro: when the program needs aspects of its own, shared functions or classes, or parallel work, write them in the same file and mark the entry point primary.
  3. Project: when the file grows too long, or other programs need its aspects or its code, move the aspects to asp/ and the shared code to a module in lib/; the aspect that you run stays as it is.
