    Design Systems and UI Libraries

    UI libraries accelerate delivery, but wrapping third-party primitives behind clear contracts prevents vendor lock-in and inconsistent interfaces.

    Bootstrap integration

    Import Bootstrap's CSS once at the application entry point (such as main.jsx) rather than importing it inside individual feature components. Avoid loading Bootstrap's imperative jQuery/DOM JavaScript bundle when React manages the DOM—use React-controlled state or a React-native wrapper like react-bootstrap for interactive modals, dropdowns, and tooltips so React never fights external DOM mutations.

    Component abstraction

    Wrap third-party UI primitives inside thin local components (for example, AppButton or StatusModal). This lets your team standardize props, enforce accessibility attributes, and swap or upgrade the underlying library later without rewriting every feature screen:

    export function AppButton({ variant = "primary", isLoading = false, children, ...props }) {
  // Restrict variants and standardize loading UX in one place
  return (
    <button
      type="button"
      className={`btn btn-${variant}`}
      disabled={isLoading || props.disabled}
      {...props}
    >
      {isLoading ? "Working..." : children}
    </button>
  );
}

    Token consistency

    Override Bootstrap's CSS custom properties (--bs-primary, --bs-body-bg, --bs-border-radius) in a single theme stylesheet instead of sprinkling ad-hoc inline styles or one-off hex colors across components. Centralizing tokens ensures dark mode, brand updates, and spacing scales stay uniform across every route.

    Upgrade strategy

    Treat UI library upgrades like API migrations: pin exact or minor-compatible versions in package.json, review breaking class or token renames in release notes, and verify key flows with visual or component tests before rolling out across the app.

    Practice

    Create a responsive dashboard shell using Bootstrap's grid, override two theme CSS variables in a central stylesheet, and build local AppButton and AppCard wrapper components used across two sample views.
