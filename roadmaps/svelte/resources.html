    Chapter 11: Svelte References

    This page is your deep-dive map. Use it to validate implementation choices against official docs and production-grade examples.

    Official Docs

    Start with primary documentation maintained by the Svelte core team whenever you need exact compiler rules, directive semantics, or SvelteKit routing and server-loading APIs:

    • Svelte Official Website — release notes, philosophy, and interactive REPL.
    • Svelte Documentation — authoritative reference for templates, reactivity, stores, and lifecycle hooks.
    • Svelte Interactive Tutorial — hands-on browser exercises covering components, transitions, and context.
    • SvelteKit Documentation — full-stack routing, form actions, SSR, and adapter deployment.

    Tutorials

    Use long-form guides to see how individual Svelte primitives fit together in multi-route applications, state stores, and form workflows:

    • FreeCodeCamp Svelte Guides — project-based walkthroughs for components, routing, and API integration.
    • YouTube Svelte Tutorials — video explanations of compiler output, stores, and SvelteKit patterns.

    Tooling

    Production Svelte repositories pair the compiler with fast build tooling, unit and end-to-end test runners, and static linting to catch accessibility and reactivity issues before deployment:

    • Vite Guide — dev server, HMR, asset bundling, and environment configuration.
    • Vitest Guide — unit and component testing compatible with Vite transforms.
    • Playwright Docs — cross-browser end-to-end tests for forms, navigation, and async UI states.
    • ESLint Docs — static analysis rules (paired with eslint-plugin-svelte and svelte-check).

    Community

    When debugging edge cases, migration questions, or library compatibility, consult active community channels and issue trackers:

    • Svelte Discord — real-time help channels for Svelte, SvelteKit, and ecosystem packages.
    • Svelte GitHub Organization — RFCs, compiler source code, and changelog discussions.
    • Svelte on Stack Overflow — searchable Q&A for common compiler and store patterns.

    Deep Dive Path

    Follow this structured sequence to move from reading examples to shipping tested Svelte features:

    1. Pick one chapter from this roadmap and implement the practice exercise in a local Vite + Svelte project.
    2. Cross-check compiler warnings, accessibility hints, and lifecycle rules against the official Svelte and SvelteKit docs.
    3. Add one Vitest or Playwright test for each interaction pattern (form validation, async loading, and error states).
    4. Run svelte-check and document one architectural trade-off (such as local state vs. shared store) in your project notes.
